\# Лабораторная работа 02. Git: индекс и история



\## Три состояния Git



\*\*Рабочая папка (working directory)\*\* — это файлы на диске, которые я вижу и редактирую.

Именно здесь появляются изменения, ещё не известные Git.



\*\*Индекс (staging area)\*\* — промежуточная область, куда я кладу изменения командой

`git add`. Индекс — это «черновик» будущего коммита: в него можно положить не все

изменения, а только нужные.



\*\*Коммит (commit)\*\* — зафиксированный снимок индекса в истории репозитория. У коммита

есть автор, дата, сообщение и уникальный хеш. После коммита изменения попадают в

историю и на них можно ссылаться.

## Git и GitHub

**Git** — распределённая система контроля версий, работающая локально на моём
компьютере. Она хранит историю коммитов, ветки и позволяет работать без интернета.

**GitHub** — облачный сервис для хранения Git-репозиториев и совместной работы.
GitHub не заменяет Git: он лишь hosting для репозиториев, pull request'ов, issue
и CI. Можно пользоваться Git вообще без GitHub.

## Использованные команды

- `git status` — показывает текущее состояние: какие файлы изменены, что в индексе,
  на какой ветке я нахожусь.
- `git diff` — показывает разницу между рабочей папкой и индексом (незастейдженные
  изменения).
- `git diff --staged` — показывает разницу между индексом и последним коммитом
  (то, что попадёт в следующий коммит).

## Ветки

**Ветка** — это подвижный указатель на коммит. Она позволяет вести отдельную линию
разработки, не трогая `main`.

При новом коммите указатель ветки автоматически сдвигается на новый коммит —
история растёт только в этой ветке.

**Слияние (merge)** объединяет изменения одной ветки в другую. При `--no-ff`
создаётся отдельный коммит слияния с двумя родителями, поэтому в истории видно,
что работа велась в ветке.
